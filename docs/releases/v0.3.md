# v0.3: Observability & Automation (draft, not tagged)

The pipeline becomes something you can watch: every run is named after its sample, every stage reports
how long it waited and ran and what it cost, and a CloudWatch dashboard and alarm show it in one place.

## Highlights
- **Runs named after the sample:** `<sample>-<UTC time>-<hash>`, with the same name in the Batch job names.
  A duplicate S3 event starts nothing. ([#65](../../../../pull/65))
- **Monitoring, deployed:** a CloudWatch dashboard (runs per day, end-to-end time, failures and durations
  by stage, console links) and one alarm on trigger-Lambda errors, deployed by scripts with `--dry-run`
  first. Per-stage queue wait, run time, cost, attempts and failure reasons come from
  `query_pipeline_duration.py --stages`. `reconcile.py` compares uploads, runs and outputs.
  ([#54](../../../../pull/54); deployed 2 Nov 2026)
- **Result quality per sample on the dashboard,** from Logs Insights queries over the stage logs, with no new
  metrics. ([#117](../../../../pull/117))
- **Log retention:** Batch and trigger-Lambda logs in Terraform-managed groups, kept 30 days.
  ([#106](../../../../pull/106), part of v1.0)
