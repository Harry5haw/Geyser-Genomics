# v0.4: Google DeepVariant Integration (draft, not tagged)

DeepVariant joins bcftools as a variant caller: first on a local NVIDIA GPU, then pangenome-aware
DeepVariant (calling against the HPRC pangenome, the project's core motivation), both benchmarked
against GIAB truth with hap.py.

## Highlights
- **DeepVariant as an alternative caller** (local GPU, CUDA; a CPU image for CI). ([#33](../../../../pull/33), *(no milestone)*)
- **Pangenome-aware DeepVariant** as a third caller, with a chr20 HPRC graph built locally with vg.
  On HG003 chr20 it reproduces Google's case study: linear DeepVariant SNP/indel F1 0.99775/0.99706,
  pangenome-aware 0.99772/0.99721 (FN −8%/−13%), bcftools 0.9915/0.9507. ([#70](../../../../pull/70))
- **HG005 benchmark** against a same-data HG003 control, with GIAB stratifications by region type. ([#95](../../../../pull/95))
- **What DeepVariant needs from the pipeline:**
  - duplicate marking in the align stage (`samtools markdup`, [#53](../../../../pull/53));
  - paired-end input end to end, from trigger pairing to the layout-aware stages ([#68](../../../../pull/68), with the trigger's S3 read access [#69](../../../../pull/69), applied).
- **Pangenome work made the top priority** in the README. ([#52](../../../../pull/52))
