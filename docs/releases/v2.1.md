# v2.1 "Hosted": the pipeline on the web, and what it shows about itself

2.1 puts the pipeline on the web. Every finished run now publishes itself to a public, read-only site on CloudFront:
**https://d1bp7nfasxklsf.cloudfront.net**. Uploads to the same site need a token. The site is static and sends a strict
content security policy. A small Lambda API answers the few things a static page can't.

2.1 is also the observability release. The CloudWatch metrics are now per stage, not per sample, so the dashboard can
show percentiles across runs. Every run record says which route it took and which caller produced the VCF. The
dashboard (36 widgets) shows the whole-genome route, the DeepVariant split, Spot retries, the GPU, spend, what's
running now, the quality gate's values and the hosted site.

**Every number below was measured on this pipeline**, in `eu-west-2`, and names its source: a pull request or a run
name. **Tagged** 9 Nov 2026.

## Highlights

**The hosted web UI** ([#213](../../../../pull/213))
- **A public, read-only showcase plus token-gated uploads**, on the default `*.cloudfront.net` domain (the user's
  choice of access model).
- **Two Terraform stacks:**
  - `infrastructure/web/` holds the site bucket, the origin access control, the response-headers policy, a
    CloudFront Function and the distribution. It has its own state, and the user plans and applies it, because
    geyser-claude's permissions boundary allows no CloudFront.
  - The dev stack holds the API Lambda, its function URL, the data lake's CORS and the Publish step.
- **The web API** (`lambda/web_api/index.py`):
  - Run status for the pages to poll.
  - Presigned **multipart** uploads straight to `raw_reads/`: 64 MiB parts, up to 64 GiB per file by default.
  - Alignment downloads (CRAM, CRAI and BAM), which need the token.
  - The token is an SSM SecureString, compared in constant time; Terraform only references it by name.
- **The Publish step:** at the end of every run, a Batch job (`geyser-publish` image) renders that run's pages with
  `manage.py publish`, writes them to the site bucket and invalidates the distribution. **Publishing is on.**
- **A strict CSP, from hashes:** `default-src 'none'`. Scripts and styles may come only from the site itself or
  match a SHA-256 hash. The publisher writes the hashes (`csp-hashes.json`, every page type) and the web stack's
  response-headers policy carries them. No inline style or script runs without its hash.
- **Every publish also writes /figures/**, so the figures page stays current. `publish --all` published 33 sample
  pages.
- **Images:** `geyser-publish` = `main-8963be1`.

**Honest pages** ([#260](../../../../pull/260))
- The first real published page (CLOUD021) contradicted itself. Step Functions had failed the run at the quality
  gate, yet the page said **Complete** and called the gate "warn mode".
- The cause: the page decided from the stage outputs alone, before it read the run record.
- The fix: the run record's close now decides the run's outcome. A gate failure in fail mode reads **Failed**:
  "The gate failed this sample, so the run failed".
- Stage times in the cloud now come from the run record's parts. They aren't summed into a total, because QC and
  align run side by side.

**Heat-map figures** ([#248](../../../../pull/248))
- The /figures/ 3D terrains, their posters and the 2D figures share one colour map: cividis, from 0.3 to 1. It is
  perceptually uniform and gets lighter at every step, so it reads in greyscale and with any colour-vision deficiency.
- An SVG colour bar now serves as the legend.

**Observability** (the observability plan's O1-O13)
- **O2, metrics per stage, not per sample** ([#249](../../../../pull/249)): `SampleId` is no longer a CloudWatch
  dimension. Dimensions are now TaskName + Status (FailureCount: TaskName only), so CloudWatch can give p50/p95
  across runs, and a new sample no longer adds billable metrics. The sample is still in the job log, the run record
  and the local metrics. The dashboard defaults to `--schema aggregated`.
- **O3, the run record says what happened** ([#251](../../../../pull/251)): `route` (small, large or
  from_alignment), `caller_outcome` (bcftools, deepvariant, pangenome, or fallback_bcftools when DeepVariant
  fell back), `infra_retries` (Batch attempts beyond the first), each stage's Batch job and attempt, and
  DeepVariant's `make_examples` counts. Every stage also logs a one-line `run-record:` summary that the dashboard
  queries.
- **O5, saved Logs Insights queries** ([#250](../../../../pull/250)): five queries in the console folder `geyser-dev`:
  - one run's timeline;
  - failures by stage;
  - Spot and host interruptions;
  - DeepVariant fallbacks to bcftools;
  - the slowest calling shards.

  All five were checked against the live logs. They cost nothing until they're run.
- **O1, dashboard v2** ([#253](../../../../pull/253)):
  - Stage groups for the whole-genome route (Preflight, AlignChunk) and the DeepVariant split.
  - Recent runs and caller outcomes from the run records.
  - Spot retries by stage from Batch's own events. On the real events, AlignChunk had 19 retries on the 4 Nov
    whole genome.
  - GPU utilisation and memory.
  - A link to the benchmark history.
- **O9, spend:** the account's estimated charges (us-east-1) against the guardrails, and links to Budgets and Cost
  Explorer.
- **O10, running now:** EC2 and Fargate vCPUs in use, and the buckets' size.
- **O11, the quality gate's values as metrics** ([#255](../../../../pull/255)): `QualityGateValue` by `Check` for
  mapped %, duplicate %, mean depth, 10x breadth and Ti/Tv, so the dashboard shows each check's value over time.
- **O13, silent upload problems as a metric** ([#254](../../../../pull/254)): `reconcile.py --publish-metrics` sends
  `ReconcileProblems` by kind (lone mates, ignored uploads, runs never started …). Zeros are sent too, so a graph
  shows 0 rather than a gap.
- **O7, the hosted site on the dashboard** ([#257](../../../../pull/257), [#259](../../../../pull/259)): the Publish
  job records Duration and FailureCount like a pipeline stage. The dashboard shows the web API Lambda, CloudFront's
  4xx and 5xx rates, and a Publish stage group.
- **O6, whole-genome rows in the benchmark history** ([#252](../../../../pull/252)): HG003 30x whole genome, bcftools
  and DeepVariant (12 hap.py rows).
- **The run record's close stored as plain JSON** ([#258](../../../../pull/258), closes #205): `Close_Run_Record`
  no longer double-encodes `Finalize.json`. The tolerant reader from #204 stays for the parts already stored.

**DeepVariant's VCF index** ([#245](../../../../pull/245))
- DeepVariant now uploads its VCF's `.tbi` beside the VCF, before the VCF itself, as bcftools always did.

**Account extras** ([#149](../../../../pull/149), the account stack, applied by the user)
- **Cost allocation tags**, so Cost Explorer can show cost per stage.
- **Cost Anomaly Detection:** the account's existing monitor imported into Terraform, plus a subscription.
- **IAM Access Analyzer.**
- **myApplications was dropped**, because AWS discontinued AppRegistry.

`main-6eaa827`); `geyser-publish` = `main-8963be1`.

| :--- | :--- | ---: | :--- |
| `CLOUD021-20261109T165337Z-05da1465` | **FAILED**, as designed | 5 min 18 s | The quality gate in fail mode stopped the synthetic sample (its profile's thresholds are for real data). The run record closed as `failed`, and the run was published. Its page is the one that #260 fixed. |
| `CLOUD022-20261109T171346Z-0cc5ea6a` | **SUCCEEDED** | 5 min 39 s | The same synthetic sample with the `smoke` gate profile: every stage, the gate and the Publish step. The page is on the site. |

**Lighthouse on the live site** ([#240](../../../../pull/240)): CI now checks Lighthouse budgets on the published static
site, the upload page included, under the strict CSP. The live site passes on `/`, `/figures/`, the CLOUD021 and
CLOUD022 pages and `/uploads/`: **LCP 0.84-0.93 s, CLS 0, TBT 0**, with a clean console under the CSP (no blocked
script or style).
